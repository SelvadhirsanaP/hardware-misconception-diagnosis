# AI-Based Hardware Misconception Detection and Diagnosis System

**VConnecTech Engineering Marathon 2026**

A software-only project designed to help students understand and diagnose common mistakes in Verilog HDL code. This project does not require any physical hardware.

---

## 1. Introduction

The AI-Based Hardware Misconception Detection and Diagnosis System is a web application that helps students learning **Verilog Hardware Description Language (HDL)** understand their hardware design mistakes.

The application uses real **Icarus Verilog** and **Yosys** tools to analyze Verilog code, identify supported issues, and provide beginner-friendly explanations.

It also supports optional Large Language Model (LLM)-based explanations. The application works without an API key using its built-in rule-based explanation system.

## 2. Problem Statement

Students often struggle with hardware design misconceptions such as unintended latches, multiple drivers, incomplete combinational assignments, and incorrect logic.

Traditional compilers and synthesis tools mainly provide technical error messages and warnings. These messages can be difficult for beginners to understand.

As a result, students may struggle to identify the actual cause of an issue and understand how to correct it.

There is a need for a learning-oriented system that explains Verilog design issues in simple language and helps students improve their debugging skills.

## 3. Proposed Solution

Our proposed system analyzes Verilog HDL code and examines the reports generated by real compilation and synthesis tools.

It identifies supported errors and potential issues, explains their root causes, introduces the related hardware concepts, and provides suggested correction templates.

The system is designed to support learning and debugging without automatically overwriting the student's original code.

## 4. Features

- Modern dark-navy dashboard with a responsive user interface.
- Code editor with line numbers.
- Sample Verilog code loader.
- Upload support for `.v` files.
- Integration with Icarus Verilog, `vvp`, and Yosys.
- Safe external tool execution using Python subprocess, without `shell=True`, with timeouts and temporary working directories.
- Detection and analysis of supported issues, including:
  - Syntax and compilation errors.
  - Unintended latch inference.
  - Multiple-driver conditions (subject to tool-report parsing and validation).
  - Incomplete combinational assignments.
  - Potential incomplete sensitivity-list issues.
  - Blocking and non-blocking assignment misuse.
  - Undriven signals and other supported synthesis warnings.
  - Functional mismatches when an appropriate testbench is provided.
- Findings are labelled as **Confirmed** when supported by tool output and **Potential** when identified through heuristic checks.
- Issue explanations may include:
  - Original code snippet.
  - Identified problem.
  - Beginner-friendly explanation.
  - Related hardware concept.
  - Learning tip.
  - Suggested correction template.
  - Reason for the suggested correction.
- Optional LLM-based explanations using Anthropic or OpenAI-compatible APIs.
- Rule-based explanations work without an API key.
- AI-generated explanations are checked for unsupported line-number references.
- Printable analysis report.

**Note:** Detection accuracy depends on the Verilog code, tool versions, and available testbenches. Not all hardware misconceptions can be identified automatically.

## 7. Prerequisites

The following software is required to run the application on Windows:

- Windows 10 or Windows 11.
- Python 3.9 or later (tested with Python 3.11.9).
- Icarus Verilog.
- Yosys.
- Git (optional, for cloning the repository).

**Important:** Icarus Verilog and Yosys must be installed and accessible to the application for tool-based analysis.

## 8. Installing Python

1. Download Python from the official website:

   https://www.python.org/downloads/

2. Run the installer.
3. Enable **Add Python to PATH** during installation.
4. Complete the installation.

Verify the installation in a new Command Prompt:

```powershell
python --version
```

The project was tested using Python 3.11.9.

## 9. Installing Icarus Verilog

Icarus Verilog is used to compile and simulate Verilog HDL designs.

1. Download a Windows build of Icarus Verilog from:

   https://bleyer.org/icarus/

2. Run the installer.
3. Enable the option to add executable folders to the user PATH, if available.
4. Complete the installation.
5. Open a new Command Prompt and verify:

```powershell
iverilog -V
vvp -V
```

Both commands should display version information.

## 10. Installing Yosys

Yosys is used for synthesis and hardware design analysis.

### Recommended method: OSS CAD Suite

1. Visit the official OSS CAD Suite release page:

   https://github.com/YosysHQ/oss-cad-suite-build

2. Download the Windows x64 release.
3. Extract the downloaded archive to a convenient location, for example:

```text
C:\oss-cad-suite
```

4. Open Command Prompt or PowerShell and run the environment setup script:

```powershell
C:\oss-cad-suite\environment.bat
```

5. Verify the installation:

```powershell
yosys -V
iverilog -V
vvp -V
```

OSS CAD Suite includes several hardware design tools, including Yosys and Icarus Verilog.

**Alternative:** Users can install the tools separately or use WSL with Ubuntu if preferred.

For WSL Ubuntu:

```bash
sudo apt update
sudo apt install yosys iverilog
```

If the tools are installed but are not automatically detected, configure their executable paths using the environment variables supported by the application:

```text
IVERILOG_PATH
VVP_PATH
YOSYS_PATH
```

Refer to `.env.example` and the application configuration for the expected values.

## 13. Optional API Configuration

The application supports optional LLM-based explanations.

To configure an API provider:

1. Copy the example configuration file:

```powershell
copy .env.example .env
```

2. Open `.env` and configure the required values:

```text
LLM_PROVIDER=anthropic
LLM_API_KEY=your_api_key
LLM_MODEL=your_model_name
```

For an OpenAI-compatible API, configure the provider and base URL according to the application's supported settings.

**Important:**

- API configuration is optional.
- The application works using rule-based explanations without an API key.
- Use a valid API key and model name from your chosen provider.
- Never upload your `.env` file or expose API keys publicly.
- Ensure `.env` is excluded through `.gitignore`.

## 14. Running the Application

Before starting the application, ensure the required hardware design tools are available in the terminal environment.

If using OSS CAD Suite, run its `environment.bat` setup script first.

Activate the Python virtual environment if it is not already active:

```powershell
venv\Scripts\activate
```

Start the Flask application:

```powershell
python app.py
```

The application starts on the local Flask development server.

Open the following URL in your browser:

```text

```

1. Enter Verilog HDL code or select a sample.
2. Upload a `.v` file if required.
3. Click **Analyze Code**.
4. View the detected issues and explanations.
5. Review suggested corrections and the analysis report.

## 17. Known Limitations

- Not every hardware misconception can be detected automatically.
- Functional and logical errors generally require a suitable testbench or a specification describing the expected behaviour.
- Static analysis uses heuristic checks and may produce false positives or miss certain cases.
- Complex Verilog constructs such as generate blocks, functions, tasks, and deeply nested code may require additional parsing support.
- Tool-output parsing depends on the message formats produced by the installed Icarus Verilog and Yosys versions.
- Multiple-driver detection may not identify every possible driver conflict accurately.
- Suggested corrections are learning templates and should be reviewed before being used.
- Certain potentially unsafe Verilog constructs, including supported forms of file inclusion, `$system`, and file I/O system tasks, are restricted by the application.
- Optional AI-generated explanations may be unavailable or inaccurate. The application uses validation and fallback explanations, but these do not guarantee that every AI response is correct.
- The project is intended for educational and demonstration purposes. It should not be exposed directly to the public internet without additional security measures such as authentication, rate limiting, and deployment hardening.
